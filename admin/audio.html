2. How should we split it?

Leave this on unless the recording is a bare voice. It listens for the voice rather than for silence, which is what lets it find the gaps even while the accompaniment keeps playing. Turning it off uses the old plain-silence method — faster, but a recording with continuous accompaniment will come back as one single piece.
If you fill in the expected count we'll tell you whether we hit it — nothing is forced to match. A chanted shloka follows a vṛtta, so it's rarely shorter than 10–15 seconds; anything shorter gets joined to its neighbour. A pause shorter than the second figure is treated as a breath inside a verse, not a boundary.
Know more — fine tuning
You shouldn't need any of this. It's here for the case where a particular recording splits badly and you'd rather fix it yourself than wait.
Loudness cut-off — anything quieter than this counts as a gap. Left blank, it's chosen from the recording itself, which is usually better than a guess.
Breathing room — each clip is extended by this much at both ends so nothing is clipped mid-syllable. It applies to the timestamps and the WAV clips alike, so both play the same audio.
How much is pause — used to work out what the background music sounds like on its own. If the recording has unusually long gaps, raise it; if it's almost wall-to-wall chanting, lower it.

4. Push to bhumandala-audio-data

Scope this token to ONLY bhumandala-audio-data. GitHub → Settings → Developer settings → Fine-grained tokens → Repository access: "Only select repositories" → bhumandala-audio-data → Permissions: Contents: Read and write. This page hardcodes its target repo (no picker), but that only helps if the token itself can't reach anywhere else — a broadly-scoped token pasted here could still write elsewhere if this page had a bug, so don't rely on the UI alone.
Pushes go through GitHub's Git Data API (blob → tree → commit, all files in one atomic commit), not the plain "upload a file" API — that raises the reliable per-file ceiling to roughly GitHub's own ~100 MB hard limit (without Git LFS), well past the 25 MB cap you'll hit dragging a file into the GitHub website (that limit is specific to the website's uploader, not the API). A single file anywhere near 100 MB still won't go through, though — use Download above instead and place it wherever you like.
Prefilled from the uploaded filename when you first pick a file — edit it to anything you like. GitHub has no real "create folder" step: typing a new path and pushing to it creates it automatically.
