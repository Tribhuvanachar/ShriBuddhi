What this does: hides gated library paths from readers who don't hold an allowed role — the same UI-level curation as the Library Manager's own "Hide" list, extended with roles. A determined visitor with the direct file URL can still fetch it; the corpus itself stays public static files either way. Reads work for everyone immediately; saving a change here needs you signed in with a Firebase account whose stored role is superadmin (firestore.rules enforces that for real, regardless of this page's own passkey).

Roles

The six built-in tiers ship with every deployment and can't be removed. Add a custom role here to use it in a content gate below — e.g. a "patron" or "sanskrit-teacher" tier.

Content gates

A gate restricts one taxonomy path (and everything under it) to the roles you tick. A path with no gate stays open to everyone, signed in or not — same default as before this page existed. The longest matching gate on a path wins.

Capabilities

A gate decides what a role may see. A capability decides what it may do. Tick the roles that may copy text out of the reader — a word, a sentence or a whole verse, from the right-click menu and the 🕉️ Genie row. An admin always can. With nothing ticked, nobody else can, which is exactly how the site behaved before this panel existed.

Test it

Instant check against the gates above, including any unsaved edits — the fast create-role → grant-access → test loop, no second account needed. This checks the DRAFT you see on this page; save below to make it real for actual visitors.

To see the actual reader as that role — not just this yes/no check — open the app after using window.dgeSetPreviewRole('role-id') in its console (superadmin only; clears on tab close, or call dgeClearPreviewRole()).
